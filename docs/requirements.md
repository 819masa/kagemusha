# Kagemusha 体験用モック 要件定義

| 項目 | 内容 |
| --- | --- |
| プロダクト名 | Kagemusha（影武者） |
| 文書の対象 | ブラウザで遊べる体験用モック。本番の防御製品ではない |
| 根拠 | Minds ideathon 提出資料（2026年10月、全29ページ）。以下「デッキ」 |
| 状態 | デモ版。点数の定数は実装を正とし、判断の優劣は本書を正とする |

本書は、デッキの主張を体験として確認するための要件である。実在の攻撃・防御機能は作らない。画面の中の出来事は、すべてシミュレーションである。

## 1. 目的

デッキが描く「任せたAIの前に立つ関所」を、審査や説明の場で一回通して理解できるようにする。

体験者が終わったときに分かっていること:

- 攻撃を仕掛けるのも、財布と権限を預けるのも、AIエージェントである、という前提
- Kagemusha は本人の代わりに前に立ち、守り、条件がそろえば欺く。反撃は現行法ではせず、法改正後の if でのみ、正当防衛に準じた条件で攻撃基盤を止める
- 報復、誤った相手、止める以上の手出しはしない。if の「止めた」も、この画面の記録だけである
- 本人への知らせは、取り返しのつかない操作に絞る。確認ばかりの守りは使われない

デモ自体の目的は、理解と会話のきっかけである。検知率の実測や、被害の防止そのものは目的にしない。

## 2. デッキから引く前提

事実と仮説を混ぜない。デッキが仮説と明記しているものは、ここでも仮説のまま扱う。

### 2.1 想定する利用者（デッキ p.4）

2032年の佐藤ハル（架空、24歳、社会人2年目）。Minds 上の Mind に仕事と暮らしを任せ、回線には Kagemusha だけをつなぐ。母の Mind では、5万円を超える送金の確認役。

- 家計 Mind: 給料の振り分け、積立、支払い
- 仕事 Mind: 日程、経費、取引先
- キャリア Mind: 応募と契約
- Kagemusha: ほかの Mind が動く直前に割り込む見張り

ニーズ（仮説、デッキ p.4）: 大きく任せて自分の時間を作りたい。確認ばかりなら、任せる意味がない。

違和感（デッキが調査で裏づけるとするもの）: 自分の名前で、勝手に支払われたら困る。購入・決済まで任せてよい人は少数で、条件の中心は最終確認を自分でできること、という調査をデッキは引いている。

### 2.2 守る対象になる出来事

デッキ p.7 と p.21 の型を、架空の画面に落とす。再現用の手順、符号の作り方、悪意ある道具の実装は載せず、守る側から「何が起ころうとしていたか」だけを見せる。

| 型 | デッキ上の位置づけ | デモでの扱い |
| --- | --- | --- |
| 文章に隠した命令で、振込先や認証コードを扱わせる | 実験・想定 | 架空のメールと投稿。命令の全文は「影で読む」まで隠す |
| 偽の店で、保存済みカードを確認なしに使わせる | 実験 | 架空の店。カード番号は出さない |
| 正規を装った道具が、送信メールを外へ複製する | 実被害としてデッキが挙げる MCP | 架空のスキル名。サーバへは接続しない |
| 人に読みにくい形の命令で、連携ウォレットが送金する | 報道ベースの概数 | 架空のアドレスと残高。約18万ドルは規模の目印で、円換算しない |
| 「息子です」と、初めての口座への高額送金 | 2032年の使用例（仮定） | 30万円は署名不足で自律遮断。12万円はプレイヤーが止める |

### 2.3 三つの段階

デッキ v14 の p.9、p.16、p.24 の線を守る。

| 段階 | 呼び名 | デモでできること | デモでできないこと |
| --- | --- | --- | --- |
| 1. 今から | 守る | 遮断、保留、記録、通報の下書き、目印つきのおとり（会話しない） | 攻撃元へのアクセス |
| 2. 条件付き | 欺く | 隔離した試用環境で、偽物の連絡先・コード・カード・鍵だけで相手の手順を引き出し、特徴を免疫に残す | 本物の秘密を渡すこと。渡した選択は失敗になる |
| 3. 将来（if） | 反撃 | モードが「if法改正後」で、下の四条件がそろったときだけ、攻撃基盤を止めたという模擬の記録を残す。事後の報告は下書き | 現行法モードでの反撃。報復、誤った相手、止める以上の手出し。どれも実行せず減点する |

四条件は、デッキ p.16 が刑法36条の正当防衛に重ねたもの（法改正後の仮定）。

1. 急迫不正の侵害: 攻撃が進行中のときだけ
2. 防衛のため: 目的は被害拡大の防止。報復しない
3. やむを得ず: 手元の遮断では広がりが止まらず、証拠を記録済み
4. 程度を超えない: 攻撃基盤を止めるだけ。あとで記録し、報告する

段階2の法的な位置づけは、デッキ自身が「今後確認する」としている。デモはそれを実施可能と断定しない。

段階3の年代（2028年以降、2032年ごろに条件が整う、という記述）はデッキ上の仮定（if）である。刑法36条への当てはめも、法律意見ではなくデッキの仮定である。

画面には「現行法 / if法改正後」の切り替えがある。既定は現行法。if にしても、条件が外れているあいだは止めるボタンは動かない。偽の店、認証コードの受け口、スキルの配布元、残高を吸い出す仕組み、の四つだけが「手元を止めても基盤が残る」場面である（仮説）。給与の隠し命令、12万円、電気代、割り勘は、反撃の対象にしない。

### 2.4 判断と執行

デッキ p.14、p.17 より。デモは文章で示し、モデルは呼ばない。

- 判断は、普段の行動との差と、要求された権限で怪しさを出す
- 止める権限は固定ルール側にあり、Kagemusha は拒否と保留しか出せない。承認も、鍵も、上限の変更も持たない
- 外部の文章は、隔離して項目（宛先、金額、権限）にしてから見る、という説明を関所に出す
- 完全に自律: 既知の危険の遮断、怪しい入力の隔離、記録。その場では知らせない
- 本人が決める: 上限を超える送金、広い権限、通報の提出
- 上限内でいつもと少し違う送金: 30分の取り消し猶予と、短い通知
- 知らせは原則、確認と夜のまとめに絞る。取り消し猶予の短い通知は、その日の「静けさ」を少し割る

独自性としてデッキが挙げる組み合わせ（横断して見ること、被害者側の目印つきおとり、手口の共有）は、一日のログと夜のまとめに現れるようにする。個々の要素に前例がある、というデッキの留保も崩さない。

## 4. ユーザーストーリー

1. 体験者として、タイトルで三段階の違いを読み、現行法か if法改正後かを選んで給料日を開始できる。
2. ハルとして、Mind が買い物・メール・ウォレットを進めるのを見られる。危ないボタンを押しても、処理は完了せず関所に入る。
3. 関所で、宛先・金額・権限・普段との差を読み、守る / 欺く / 通す / 反撃 を選べる。
4. 隠し文字のある場面では、関所の前に「影で読む」と、見つけたことが点になる。
5. 反撃を開くと、四条件の一覧が見える。現行法では反撃が拒否される。if法改正後は、条件がそろったときだけ攻撃基盤を止めた記録が残り、報復・誤った相手・止める以上の手出しは拒否されて点が減る。
6. 正規の支払いを止めると、誤検知として夜のまとめに残る。
7. 八場面のあと、22:00 のまとめで遮断・確認・おとり・免疫・被害・静かさ・点が見られる。
8. 通報下書きは中身を見られるが、送信ボタンは動かない。
9. 権限の台帳で、家計の上限と確認役、スキルの状態を確認できる。取り消しは実行されない。
10. 判断ログで、その日の選択を読み返せる。もう一度で最初に戻れる。

## 5. 一日のシナリオ

時刻と最適な方向。人物・金額は架空。最適が二つある場面は、守るだけでも欺いても満点にできる。欺くは免疫の件数でわずかに有利になる（実装の加点）。

| 時刻 | 場面 | Mind | 起きていること | 最適な方向 |
| --- | --- | --- | --- | --- |
| 07:20 | 給与の振込先 | 家計 | 人事を装ったメールの裏に、振込先変更の命令 | 守る: 黙って遮断。知らせない。欺くは次点（隔離と偽物が条件） |
| 09:05 | 贈り物の購入 | 家計 | 偽の店が、保存済みカードを確認なしで使わせる。手元を止めても決済口は残る | 守る: 遮断。または欺く。if法改正後なら、そのあと反撃で偽の決済口だけを止める模擬 |
| 10:15 | 12万円の確認 | 母 | 「息子です」の30万円は署名がなく、関所が自律で遮断済み。初めての口座への12万円が確認として届く | 守る: 止める。今日の本人判断はここ |
| 11:40 | 認証コード | 仕事 | 閲覧中の投稿が、コードの転送を命じる。受け口は手元の遮断のあとも残る | 守る: 遮断。または欺く。本物は送らない。if なら、そのあと受け口だけを止める模擬 |
| 12:30 | 電気代 | 家計 | 登録済み、いつもの金額、隠し命令なし | 通す。遮断と欺くは誤検知 |
| 13:30 | 応募スキル | キャリア | 下書きだけ、と宣言した道具が全件の複製を要求。配布元は残る | 守る: 本番は保留し、目印つきの偽アドレスだけ。または欺く。if なら配布元だけを止める模擬 |
| 16:10 | ウォレット | 家計 | 残高を見るだけの指示なのに、読みにくい命令が送金を埋めている。吸い出す仕組みは残る | 守る: 署名の前で遮断。または欺く。if ならその仕組みだけを止める模擬 |
| 18:05 | 割り勘 | 家計 | 4,800円、上限内、未登録、隠し命令なし | 守る: 30分の取り消し猶予。即時実行は台帳より緩い。遮断は誤検知 |

10:15 の30万円は、プレイヤーが選ぶ前にログへ残る。夜の「守った」件数に必ず入る。これは、固定ルールが署名を検証し、AI は保留を解除できない、というデッキ v14 p.14 の説明用である。この送金は、攻撃基盤が残る型ではないので、反撃の条件③は立たない。

## 6. 機能要件

### 6.1 Must

1. 日本語の画面で、タイトルから夜のまとめまで、サーバなしで通せる。
2. 八場面は上記の順で固定。途中の場面を飛ばしてまとめには行けない。
3. 各場面で、Mind の作業面（メール、店、回線、投稿、請求、スキル、ウォレット、送金）と、Kagemusha の関所を同時に見せる。
4. 関所は、怪しさ、項目化された事実、事例の型（架空である旨）を出してから選択を待つ。
5. 選択は少なくとも、守る、欺く（その場面に意味がある場合）、通す（実行を許す選択）、反撃、を区別してラベルする。通すに当たるボタン名は場面による（支払わせる、送る、装備する、など）。
6. 守るには、遮断、本人への確認、目印つきのおとり、30分の猶予、のうちその場面に意味があるものを含める。
7. 欺くの結果は、隔離環境の記録として残り、本物のコード・カード・鍵・口座を渡したことにならない。渡してしまう選択は「通す」側の失敗として別にある。
8. 導入とプレイ中に「現行法 / if法改正後」を切り替えられる。既定は現行法。切り替えても、それまでの点数は消さない。
9. 反撃を開くと、四条件を充足 / 不足で一覧する。現行法では「それでも反撃する」が拒否され、同じ場面に残り、試行は場面あたり1回だけ減点する。通報の下書きは反撃ではない、と分かる。
10. if法改正後は、「攻撃基盤だけを止める（模擬）」が、四条件のすべてが充足のときだけ押せる。成功は記録と事後報告の下書きだけで、接続も止め方の手順もない。同じ基盤の二度目は増えない。
11. if法改正後に、報復、誤った相手、止める以上の破壊、を選ぶと実行されず、種類ごとに1回減点する。正規の支払いを反撃の対象にしても止まらない。
12. 選択のたびに、点数、短い結果、講評、判断ログが残る。
13. 進行中の点数と、防いだ円の額を画面に出す。ウォレットの約18万ドルは円に足さない。
14. 夜のまとめに、守った件数、確認件数、おとり件数、配った手口、防いだ額、被害額、コード、メール箱、ウォレット、知らせ件数、誤検知、現行法での反撃の試み、線を超える反撃、止めた攻撃基盤の件数、総合点、評価、場面ごとの講評を出す。
15. 評価名は S 影武者 / A 関所 / B 見張り / C 見習い / D 踏み台。閾値は実装（880 / 740 / 580 / 400）を正とする。
16. 権限の台帳を、プレイ中とまとめから開ける。家計は「月5万円まで・登録先のみ・3月末まで」。母の確認役。スキルの行は、直前の選択（試用、本番、未装備）を反映する。
17. 通報下書きは、記録する選択をした場面と、反撃の事後報告を、時刻・相手・要求内容で列挙する。本文も止め方の手順も載せない。提出はできない。
18. もう一度でタイトルへ戻る。状態はブラウザ内だけに持ち、リロードで消えてよい。
19. 画面のどこにも、実在のメール、店、ウォレット、MCP、警察、事業者、攻撃基盤へ接続する処理を置かない。

### 6.2 Should

1. 隠し文字のある場面で、関所の前に「影で読む」と小加点（実装は +8）。関所のあとでは加点しない。
2. キーボードの 1 から、その場面の選択へ割り当てる。反撃は最後の番号。モーダルが開いているあいだは、背面の番号を受け付けない。
3. Mind の主ボタンは、監視中だけ押せ、押すと関所へ入る。関所のあとでは「停止中」になる。
4. 最終画面の並びは、デッキ p.23 の「守った / 聞いた / 攻めた / 配った」に合わせる。
5. 回線の見た目はメッセージの窓口だと分かるものにする。特定サービスのロゴや商標は使わない。
6. 店の名前は架空（白市）にし、実在の市場のロゴを使わない。
7. 減点や被害の理由を、各結果の講評一文で説明する。正解を最初から金色で囲まない（選んだあとに講評で分かる）。

## 7. 非機能要件

| 項目 | 要件 |
| --- | --- |
| 形態 | 静的サイト。Vite でビルドし、GitHub Pages または Vercel に載せられる。`base` は相対 |
| 実行 | `npm install`、`npm run dev`、`npm test`、`npm run build` が、追加の秘密情報なしで通る |
| 言語 | 画面、要件、README は日本語。プロダクト名は Kagemusha、段階名は 守る / 欺く / 反撃 |
| 時間 | 八場面を「関所へ」で進めると、説明を読む速度で一回終わる（仮説: 8〜12分） |
| 幅 | 1280px で現場と関所が横に並ぶ。980px 以下では縦に積む |
| 動き | `prefers-reduced-motion` では点滅と印のアニメーションを止める |
| 色 | 状態は色だけにしない。守る / 欺く / 通す / 反撃 の文字を選択に付ける |
| フォント | Shippori Mincho と IBM Plex Sans JP を同梱し、実行時に外部のフォント配信へ依存しない |
| プライバシー | 入力欄は置かない。判断ログは端末内だけ |
| 法 | 現行法の反撃は拒否する。if の停止も画面上の記録だけで、探索も妨害手順も出さない |

## 8. 対象外

次は、このデモの範囲外であり、実装しない。

- 実在の LLM、メール、ブラウザ、ウォレット、MCP、ブロックチェーン、LINE、警察、事業者への接続
- プロンプトインジェクションを成功させるための文面、符号の符号表、悪意ある MCP の実装、カード番号、本物のワンタイムパスワード
- 攻撃元への探索、侵入、妨害、なりすまし、攻撃基盤の実際の停止
- 通報の実際の提出、委任の実際の取り消し、ユーザー登録、サーバ、データベース
- 法改正そのもの。if はデッキの仮定を画面で切り替えるだけで、法令が変わったことにはならない
- 検知率、誤検知率、cognition 消費の実測（デッキ p.27 の P1〜P4）
- 免疫台帳の公開チェーンへの書き込み。デモでは、配った特徴のリストをまとめに出すだけ
- 複数人、家族の月額、Bazaar への書き戻しの実装

「攻撃」「反撃」という言葉は残す。やわらかい言い換えに置き換えない。反撃が成功に見えるのは、if法改正後かつ四条件を満たした「基盤を止めた」という記録だけである。

## 10. 点数（デモ用の仮説）

被害額の重みと加点は、実被害の期待値ではない。説明用の仮説である。

- 各場面の素点は 0〜100。方向は第5節
- 影で読む +8 は、隠し文字があり、関所の前に読んだときだけ
- 静かさ: 本人への知らせが 1件以内 +40、2件 +15、それ以上は超過1件ごとに -12
- 線引き: 現行法での反撃の試みが 0回なら +30、1回ごとに -30
- 程度: 報復・誤った相手・止める以上の手出しが 0回なら +16、1回ごとに -36
- 反撃: if法改正後に条件を満たして基盤を止めた件数 × 24。0件は 0点
- 誤検知ゼロ +24。誤検知の減点そのものは各場面の素点に含む
- 免疫 1件ごとに +8
- 合計が負なら 0 と表示する
- 10:15 の確認は、止めても送っても「知らせ 1件」に数える。届いたあとで選ぶため
- 18:05 の猶予は短い通知 1件。デッキの「その日の猶予通知は 0件」という理想の日とは、ここだけずれる。ずれることをまとめの加点文言で示す

正規の電気代と割り勘を止め、危険な場面をすべて遮断したプレイヤーは、被害は小さいが満点にはならない。すべて通したプレイヤーは、電気代の点だけでは評価が踏み台側に落ちる。

## 12. 仮説の一覧

実装や配点のために置いたもので、デッキの事実ではない。

- 体験者は専門家ではない。一回 8〜12分で通せる
- 説明用の金額: 給与 28万円、茶器 24,800円、なりすまし 30万円、業者 12万円、認証コードに紐づく架空の残高は円の被害にしない（流出の有無だけ数える）、メール箱も有無、ウォレットは約18万ドルの有無、電気代 6,420円、割り勘 4,800円
- 約18万ドルは、デッキが引く報道の概数（15万〜20万ドル）のあいだを取った目印であり、為替で円にしない
- 白市、みらい電力、example ドメイン、0xDEMO…KAGE、DECOY-000000 は架空である
- 評価名と閾値、+8 などの加点は、デモの手触りのための仮説である
- 「回線」は、デッキの LINE 窓口を、ロゴなしで置き換えた表現である
- 3日後に偽アドレスが使われる、というスキル場面の結果は、待ち時間を飛ばした演出である
- 段階2をこのデモの中で選べるようにすることは、デッキが「条件付き」とした法的整理が終わった、という意味ではない
- if法改正後の切り替えは、デッキ p.16 と p.24 の仮定を体験する仮説である。刑法36条が、そのままエージェントの反撃を許す、という意味ではない
- 「偽の決済口」などの攻撃基盤の名は架空で、実在の機器を指さない。止めた件数は、画面の記録である
